# ADR-001 — Phased Roadmap, Correctness Before Cosmetics

**Status:** Accepted
**Date:** Phase 1 kickoff

## Context
MediBot started as a single-file Streamlit + CLI app. A full rewrite risked losing working RAG behavior.

## Decision
- Execute a phased roadmap (1 backend → 2 LLM → 3 guardrails → 4 memory → 5 eval → 6 UI last).
- Refactor incrementally: reuse existing RAG/ingestion/embeddings logic, don't rewrite.
- UI redesign is deliberately last — new backend states (intent, memory, SSE) must exist before designing against them.

## Consequences
- Working system at every phase; UI only needs one finish-pass. Downside: Phase-1-era UI temporarily lags backend capability.
